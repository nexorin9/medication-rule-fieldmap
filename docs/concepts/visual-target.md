# 视觉目标卡 · 合理用药审方字段对照系统

> **图像能力说明**：当前运行环境**不具备图像生成能力**，因此本目录**只落这张结构化视觉目标卡**，**不生成、不伪造任何概念图**。Phase 4 采集到的**真实运行截图**属于另一个目录 `docs/screenshots/`，两者不得互相冒充。

- **交付形态**：事件驱动守护（常驻进程 + 心跳 + 批次事件流 + 推送回执）
- **画面类型**：**服务运行日志（终端会话）** —— 与交付形态一致
- **不是**：浏览器面板、一次性表格导出页、桌面窗口

---

## 三个状态

### 1. 起始态

终端里 `python -m med_rule_fieldmap.daemon` 起进程。首屏是一行 banner：产品名 + 规则行条数 + 入站目录 + 出站回写目标；随后是等间隔心跳行：

```text
合理用药审方字段对照系统 · 规则 12 条 · 入站 /path/inbox · 回写 {HIS_BASE_URL}
[alive] 规则 12 条 · 已处理 0 批 · 待判定 0 条
```

画面上有什么：**一行 banner（最亮）+ 若干行心跳（最暗灰）**，没有表格、没有进度条。

### 2. 首个可用瞬间

落地目录出现一批医嘱事件文件 → 进程打印批次摘要行（收到多少行 / 合规多少 / 违规多少 / 不可判定多少）→ 逐行判定（**缩进一格**，每行带处方号与判定结论）→ 打印三份台账落盘路径 → 打印企业微信推送摘要行（推给谁、摘要几行）。

```text
批次 <批次号> 收到 200 行 · 合规 151 · 违规 21 · 不可判定 28 · 耗时 1.8s
  判定 <处方号> · RX-SKIN-TEST · 违规 · 皮试结果为「未注明」
  判定 <处方号> · RX-LIMIT-MA-OUT · 不可判定 · 缺少 rx_type|drug_category|days_qty
台账落盘 out/judgement_ledger.csv · out/undeterminable_ledger.csv · out/field_gap_priority.csv
推送 企业微信 · 批次摘要 4 行
```

画面上有什么：**一行加粗的批次摘要 + 一批缩进的逐行判定 + 两行路径回执**。

### 3. 成形态

常驻进程持续心跳；每批次稳定产出「判定台账」与「不可判定台账」两份可下载文件；不可判定项按**缺失字段聚合**成一张「接口补齐顺序表」推给信息科；药师确认后回写 HIS 并打印回执行；出站失败按退避重试，超次落 `pending_writeback` 并打红字告警。

**终态是常驻的、状态留存的、产物可带走的**，不是「跑一次出一张表」。

```text
[alive] 规则 12 条 · 已处理 7 批 · 待判定 0 条
批次 <批次号> 收到 200 行 · 合规 151 · 违规 21 · 不可判定 28 · 耗时 1.8s
  ...
回写 HIS · <处方号> · RX-SKIN-TEST · 已回写
[alert] pending_writeback 入队 1 条 · 重试 3 次 · 最后错误 500
```

## 视觉语言

### 配色（终端 ANSI）

| 用途 | 色值 | 说明 |
|---|---|---|
| 背景 | `#0F1115` | 终端主题默认深色底 |
| 正文 | `#D5D9E0` | banner 主文案、逐行判定正文 |
| 判定完成（合规 / 违规） | `#3FB950` | 绿 |
| 不可判定 | `#D29922` | 琥珀 —— 「判不了」是**中性偏警示**，不是错误 |
| 回写成功 | `#39C5CF` | 青 |
| 错误 / 告警 | `#F85149` | 红 —— 出站失败、超次重试、完整性挂起 |
| 审计与心跳行 | `#8B949E` | 最暗灰、最小字号 |

### 字体族

等宽（JetBrains Mono / SF Mono / Menlo 回退），12–13px，行高 1.4。**数字用等宽对齐**，行内对齐批次计数与耗时。

### 信息层级

1. **批次摘要行** —— 最显眼（加粗 + 正文色）
2. **逐行判定** —— 次级（缩进一格 + 正文色）
3. **回执、审计与心跳行** —— 最暗灰、最小字号

### 留白密度

同一批次内连续不空行；**批次之间空一行**；心跳行每 30 秒一行（间隔由 `MRFM_HEARTBEAT_SEC` 配置），紧随批次输出之后。

## 必须可达的约束

- 全部效果**只用当前依赖就能做出**：Python 标准库 + `rich`（或纯 `logging` + ANSI 色）即可渲染上述层级与配色，**不需要**任何前端框架、不需要 WebGL / 图表库、不需要 GPU。
- **不画产品里不存在的界面**：常驻进程没有图形界面，所有「看板」类元素一律以日志行与导出文件体现。
- 色值取自终端主题可实现的标准 ANSI 16/256 色范围；心跳间隔、推送渠道、出站重试次数均为配置项（环境变量），**不承诺超出依赖能力的动画或交互**。
- 视觉目标卡中的行号、耗时、目录路径、规则条数均为**示意值**；真实运行值以 `docs/screenshots/` 的实测截图为准。
